第 9 课：告警闭环——数字孪生的灵魂时刻

前面学的零件，这节课组装成一台完整机器：模拟感知 → 波纹+染红 → 定位 → 处理还原。这四步就是答辩时讲的"感知-呈现-定位-处置闭环"，评委看到这一幕就懂了你在做什么。

先玩一玩 👇（等 3 秒会自动来一条告警；也可手动）

然后在下方告警列表里点「📍定位」和「✔处理」

    一、先看清这台机器的四个齿轮

    ① 感知:模拟 IoT 推来一条告警
    (真实系统=传感器/WebSocket)    → ② 呈现:楼染红 + 波纹扩散
    (第4课材质 + 第8课配方B)    → ③ 定位:点「定位」镜头飞到现场
    (第2课 flyTo)    → ④ 处置:点「处理」消警还原
    (第7课材质还原思想)

    你会发现：没有新知识点，全是旧零件的新组合——这就是"组装"课的意义，也印证了第 0 课那张三层图。

    二、核心代码导览（比前几课长，但每段都似曾相识）

    ① 感知：造一条告警（数据结构设计）

    function spawnAlarm(building, tpl) {
  const alarm = {
    id: 序号++,
    type: tpl.type, level: tpl.level, desc: tpl.desc,   // '消防'/'高'/'烟感报警...'
    building: building,            // ★ 把"楼"整个对象挂在告警上(而不是只存名字)
    time: new Date().toLocaleTimeString('zh-CN', { hour12: false }),
    resolved: false,
  };
  // 呈现 + 入列(往下看)
}

    设计要点：对象里挂对象（告警挂着楼）。这样后面"定位/处理"时直接 alarm.building 就能拿到坐标和实体，不用来回查表。

    ② 呈现：染红 + 波纹（两行旧代码）

    // 染红:第7课"换皮肤"思想,把原色记在楼身上方便还原
building._origColor = building.ent.polygon.material;      // 先存原皮肤
building.ent.polygon.material = Cesium.Color.fromCssColorString('#ef5350').withAlpha(0.85);

// 波纹:第8课配方B,函数化打包成 addPulse(lon, lat),返回 {remove()}
alarm.pulse = addPulse(...offsetLL(building.dx, building.dy));

    ③④ 定位与处置：一个函数包一件事

    function focusAlarm(alarm) {   // 定位:飞到告警楼
  viewer.flyTo(alarm.building.ent, {
    offset: new Cesium.HeadingPitchRange(0, Cesium.Math.toRadians(-55), 260),
  });
}
function resolveAlarm(alarm) { // 处置:消波纹 + 还原楼 + 标记已处理
  alarm.pulse.remove();
  alarm.building.ent.polygon.material = alarm.building._origColor;
  alarm.resolved = true;
}

    界面联动：告警列表的按钮怎么"知道"自己对应哪条告警？

    网页部分用"事件委托"：列表整体监听点击，从被点按钮的 data-id 属性里查出对应告警——

    document.getElementById('alarmList').addEventListener('click', (e) => {
  const btn = e.target.closest('button');            // 点到的是哪个按钮
  if (!btn) return;
  const alarm = alarms.find(a => a.id == btn.dataset.id);  // 按编号找告警
  if (btn.dataset.act === 'focus')   focusAlarm(alarm);
  if (btn.dataset.act === 'resolve') resolveAlarm(alarm);
  renderList();                                       // 处理后重新画列表
});

    三、"随机告警"怎么来？定时器 + 随机数

    setInterval(() => {                        // 每 8 秒
  if (未处理告警数 >= 3) return;             // 别堆太多
  if (Math.random() < 0.6) {                 // 60% 概率
    const b = BUILDINGS[Math.floor(Math.random() * BUILDINGS.length)]; // 随机挑楼
    const t = TEMPLATES[Math.floor(Math.random() * TEMPLATES.length)]; // 随机挑类型
    spawnAlarm(b, t);
  }
}, 8000);
    真实系统里,这个 setInterval 的位置换成 WebSocket 消息回调: socket.onmessage = (e) => spawnAlarm(...)——业务代码一行不改。这就是"接口收敛"的价值。
    真实项目 alarmManager.js 就是本课的满血版:多了告警上限/去重/处理超时自动清理, 波纹三圈相位错开、高危红色低危橙色,楼栋染红也分级。答辩演示到"定位→处理"这一幕时, 记得停顿一秒让评委看清楼从红变回蓝——这是全场最有"数字孪生味"的瞬间。

    检查点

    1. "定位"功能用的其实是哪课的知识？

    第 2 课的相机 flyTo（套了个 HeadingPitchRange 控制距离和俯角）。

    2. 为什么告警对象里挂整个 building 而不是只存楼名？

    直接引用 = 定位/处理时一步到位拿到实体和坐标；存名字还得再查一遍表。对象挂对象是业务代码的基本功。

    3. 接真实告警系统时,哪些代码不用改？

    呈现、定位、处置全部不用改（它们只关心"告警对象长什么样"）。只改数据来源：setInterval 换成 WebSocket 回调。
