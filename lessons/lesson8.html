第 8 课：动画——让场景"活"起来

巡逻车跑起来、波纹扩散开，数字孪生的"生命感"全来自这课。同时这也是避坑课：有三个"看起来很官方"的写法，在这台电脑上会让画面全黑——我会教你怎么绕，以及为什么。

先玩一玩 👇（一辆巡逻车 + 一圈告警波纹）

右上角有 FPS 帧率角标 · 波纹在校园中心扩散

一、动画的本质：每秒 60 次"改属性"

屏幕动画 = 每秒把画面重画约 60 次（60 FPS）。Cesium 自己负责"重画"，你只需要在每次重画前把物体的属性改成"这一刻应有的值"。Cesium 给了一个"重画前"的钩子：

viewer.scene.preUpdate.addEventListener(function () {
  // 每一帧渲染前都会执行这里(每秒约60次)
  // 写法套路:用当前时间算出"现在该在哪/多大/多透明",然后赋值
});

时间从哪来？Date.now() 返回"1970年至今的毫秒数"——一个永远匀速增长的数字，除以 1000 就是秒。动画的灵魂公式：

const t = Date.now() / 1000;        // 现在(秒)
const 角度 = t * 速度;               // 匀速转圈
const 位置 = 算圆周上的点(角度);      // 三角函数派上用场

二、安全配方 A：移动的巡逻车（Primitive + modelMatrix）

让一个盒子沿圆周跑。两个新面孔：Primitive（更底层的图元）和 modelMatrix（位置姿态矩阵）。你可以把矩阵理解成物体的"传送门"——几何体永远不动，每帧把传送门挪到新位置：

// ① 创建:一次性的静态几何(黄色盒子)
const prim = viewer.scene.primitives.add(new Cesium.Primitive({
  geometryInstances: new Cesium.GeometryInstance({
    geometry: Cesium.BoxGeometry.fromDimensions({
      dimensions: new Cesium.Cartesian3(8, 4, 4),     // 8×4×4 米
      vertexFormat: Cesium.PerInstanceColorAppearance.VERTEX_FORMAT,
    }),
    attribute: Cesium.ColorGeometryInstanceAttribute.fromColor(
      Cesium.Color.fromCssColorString('#ffca28')),     // 金黄色
  }),
  appearance: new Cesium.PerInstanceColorAppearance({ closed: true, translucent: false }),
}));

// ② 每帧:算新位置 → 更新传送门
const hpr = new Cesium.HeadingPitchRoll(0, 0, 0);    // 朝向(机头方向)
viewer.scene.preUpdate.addEventListener(function () {
  if (!prim.ready) return;                            // 几何还在后台构建时先等等
  const t = Date.now() / 1000 * speedNow;             // 当前时间×速度倍率
  const a = t * 0.6;                                  // 圆周角度(弧度)
  const [lon, lat] = offsetLL(Math.cos(a) * 90, Math.sin(a) * 90); // 半径90米的圆周
  const pos = Cesium.Cartesian3.fromDegrees(lon, lat, 2.2);        // 离地2.2米
  hpr.heading = -a;                                   // 车头始终朝前进方向(切线)
  prim.modelMatrix = Cesium.Transforms.headingPitchRollToFixedFrame(pos, hpr);
});
  1. Math.cos(a) × 90, Math.sin(a) × 90 —— 高中三角函数：(cos, sin) 正好绕单位圆转，乘 90 就是半径 90 米的圆周。这就是"匀速圆周运动"的代码形态。
  2. prim.ready —— Primitive 的几何在后台异步构建，没建好就改矩阵会报错，先检查。
  3. headingPitchRollToFixedFrame(pos, hpr) —— 生成"站在 pos、朝向 hpr"的传送门矩阵。heading 就是第 2 课的"摇头角"。
  4. 精髓：几何只创建一次，每帧只改一个矩阵——成本极低，100 辆车一起跑都不卡。

三、安全配方 B：扩散波纹（Billboard 逐帧改 scale/color）

Billboard（布告板）= 一张永远面向你的贴片，最适合做图标和特效。波纹 = 一张圆环图片 + 每帧改大小和透明度：

// ① 用 canvas 现画一张 128×128 的白色圆环图(不用求任何图片素材!)
function ringCanvas() {
  const cv = document.createElement('canvas');
  cv.width = cv.height = 128;
  const g = cv.getContext('2d');
  g.strokeStyle = 'white'; g.lineWidth = 7;
  g.beginPath(); g.arc(64, 64, 55, 0, Math.PI * 2); g.stroke();
  return cv;
}

// ② 挂到场景(注意两个关键参数)
const bbs = viewer.scene.primitives.add(new Cesium.BillboardCollection());
const ring = bbs.add({
  position: Cesium.Cartesian3.fromDegrees(...offsetLL(0, 0), 2),
  image: ringCanvas(),
  sizeInMeters: true,        // ★ 用"米"而不是像素来量大小
});

// ③ 每帧:0→1 循环的进度 f,控制放大+变透明
viewer.scene.preUpdate.addEventListener(function () {
  const f = (Date.now() / 1600) % 1;                 // 1.6秒一个周期
  ring.scale = (20 + f * 200) / 128;                 // 世界直径 20→220 米
  ring.color = Cesium.Color.RED.withAlpha(0.6 * (1 - f)); // 越大越透明
});
必坑:scale 的单位是"米/像素"。图是 128 像素宽,想要 200 米的世界宽度, scale = 200 ÷ 128 ≈ 1.56。我们第一次直接写了 200,结果画出一个 25 公里的巨环盖住整个屏幕—— 记住公式:scale = 想要的米数 ÷ 图的像素宽。

四、🕳 三个"官方写法"的坑（重要，答辩也讲得）

以下写法在 Cesium 教程里随处可见，但在这台电脑（Cesium 1.144 + 这块显卡）上会导致整个场景黑屏——画面全黑但代码不报错、帧率还正常，极难排查（我们用"逐个功能开关二分法"才抓到）。课程与真实项目全部绕开：

危险写法本来想干嘛安全替代
CallbackProperty 驱动实体位置/半径/形状让实体"每帧自动变"静态几何 + 每帧改 modelMatrix / scale / color(本课配方)
裸 Primitive 装 CircleGeometry / PolygonGeometry画圆形/多边形贴片用 Billboard 贴图代替(配方B)
每帧调 camera.rotateRight()自动环绕巡航隔几十秒 camera.flyTo 转个角度(转台式巡航)
为什么讲这个?一是你在这台电脑上写就会踩;二是答辩被问"为什么不用官方的 CallbackProperty", 你能讲出"实测发现兼容性问题并给出工程绕行方案"——这是满满的工程素养分。
真实项目 patrol.js(巡逻)和 effects.js(波纹/雷达)就是本课两个配方的"满血版": 巡逻车沿不规则路线走(路线用"里程参数化"而不是圆周),波纹一次三圈相位错开,雷达是旋转的楔形贴图。

检查点

1. 为什么动画代码要写进 preUpdate 监听器,而不是写一遍就完事?

因为动画是"每帧改一点":preUpdate 每帧渲染前触发一次,你的代码每秒执行约 60 次,每次都把物体属性更新到"当前时刻应有的值"。

2. 128 像素的圆环图想要 100 米宽,scale 写多少?

100 ÷ 128 ≈ 0.78。

3. Primitive 动画为什么"几何只建一次、每帧只改矩阵"?

重建几何(顶点数据)要重新上传显卡,昂贵;改矩阵只是改一个"摆放指令",极廉价。这是 3D 引擎性能的第一常识。
